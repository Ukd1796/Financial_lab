⏺ Sure. Let me strip out the jargon.

  The core problem we're solving: Today QuietBrk has 0 wins because it looks at
  the same stocks Breakout looks at. Whenever it tries to enter, Breakout has
  already entered (or will enter on the same bar) and "owns" the position. To
  make QuietBrk actually contribute, we need to point it at a different pool of 
  stocks — stocks Breakout would naturally ignore because they're too quiet for
  Breakout's "I want big loud moves" criteria.

  To do that, we use signals already computed on each stock:

  - atr_ratio = how much the stock moves in a typical day, as a % of its price.
  Think "daily wiggle". 1% = sleepy. 5% = wild.
  - rolling_vol_5d = how choppy the stock has been over the last 5 days. Low =
  calm. High = jumpy.
  - daily_return = how much the stock moved today.
  - relative_volume = today's trading volume vs its normal 20-day average. 1.0 =
   normal day. 2.0 = double normal (something's happening).

  Now the three options — they're all answers to "how strict should we be when
  defining 'quiet'?"

  ---
  Option 1 — Strict low-vol + low-range

  ▎ "Give QuietBrk only the sleepiest stocks in the market."

  We pick stocks where:
  - Daily wiggle is in the bottom third of all stocks (super calm)
  - 5-day choppiness is below median (steady, not jumpy)
  - Today's move is less than 1% (boring day)
  - Volume is roughly normal (not too dead, not spiking)

  What this means in practice: We give QuietBrk maybe 15–30 stocks per day — a
  small, very clean pool of "boring drift-up candidates". These are guaranteed
  to be different from Breakout's stocks, because Breakout demands a stock move
  >1.5% today on >50% extra volume — none of these would qualify.

  Risk: On busy market days (lots of volatility), almost nothing qualifies as
  "quiet enough" and QuietBrk runs out of names to look at. The 20-day breakout
  signal needs a deep enough pool to find any actual breakouts.

  ---
  Option 2 — Quiet-but-not-dead band (my recommendation)

  ▎ "Give QuietBrk the stocks in the middle of the activity spectrum — not the 
  ▎ loudest, but not the deadest either."

  We pick stocks where:
  - Daily wiggle is in the 25th–60th percentile (middle of the pack)
  - 5-day choppiness is in the 25th–60th percentile (also middle)
  - Today's move is less than 1.5% (moderate, not explosive)
  - Volume is roughly normal-ish

  What this means in practice: We give QuietBrk maybe 30–50 stocks per day — a
  wider pool of "stocks that are moving, but not in the loud breakout way
  Breakout cares about". This is the "slow grinders" cohort.

  Why I recommended this: QuietBrk's signal is a 20-day high breakout — it needs
   stocks that are actually grinding upward over weeks, just without the daily
  fireworks. The lower band ("dead stocks") rarely produces 20-day highs because
   they're not going anywhere. The middle band is where slow uptrends actually
  live. Plus, more candidates = more chances for the signal to fire.

  ---
  Option 3 — Hybrid (quiet primary + breakout fallback)

  ▎ "Try to give QuietBrk the quiet slice. But if too few qualify, top up with 
  ▎ whatever Breakout would relax to."

  We start with Option 1's strict quiet slice. If fewer than 10 stocks qualify
  (busy market day), we fall back to the current relaxed-Breakout filter to fill
   out the pool.

  What this means in practice: QuietBrk always has at least 10 stocks. But on
  the days when the fallback kicks in, we're back to today's broken behavior —
  those topped-up stocks overlap with Breakout's universe, and QuietBrk loses to
   Breakout on the merge again.

  Why I'd avoid this: The fallback fires exactly on the days when carve-out
  matters most (when the market is busy and Breakout is hogging everything).
  It's a self-defeating safety net.

  ---
  Plain-English summary of the three:

  ┌──────────────┬─────────────┬─────────────────────┬─────────────────────┐
  │    Option    │  Pool size  │ Distinctness from   │        Risk         │
  │              │             │      Breakout       │                     │
  ├──────────────┼─────────────┼─────────────────────┼─────────────────────┤
  │ 1. Strict    │ Small       │ Total               │ Runs thin on busy   │
  │ low-vol      │ (~15–30)    │                     │ days                │
  ├──────────────┼─────────────┼─────────────────────┼─────────────────────┤
  │ 2. Middle    │ Medium      │ High                │ Mild overlap on     │
  │ band         │ (~30–50)    │                     │ rare days           │
  ├──────────────┼─────────────┼─────────────────────┼─────────────────────┤
  │ 3. Hybrid    │ Always ≥10  │ Partial             │ Overlap returns     │
  │              │             │                     │ when it matters     │
  └──────────────┴─────────────┴─────────────────────┴─────────────────────┘

  Does that clear it up? Once you pick a quiet criterion, the second question
  (strict carve vs soft carve) is just about how we make sure Breakout gets
  first dibs when there's any overlap — but with Option 1 or 2 the overlap is
  small enough that either mechanism works.

     Plan — QuietBrk Universe Carve-Out (Middle-Band Quiet Filter)

     Context

     QuietBreakoutStrategy is dead weight in the ensemble. Standalone, it
     produces Sharpe 2.01 in Crash 2020 (+32%) and Sharpe 2.45 in Recov 2021
     (+94%). Inside the multi-strategy router it contributes 0 wins across all
     periods (36k–44k signals issued, 0 entries owned).

     Root cause (confirmed by reading the universe and router code, not
     assumed):

     1. run_ujjwal_baseline.py:160-166 wires two universe filters into the
     union: a primary BreakoutUniverseFilter(top_n=20) and a "QuietBrk slot"
     that is literally a relaxed-threshold copy of the same class
     (BreakoutUniverseFilter(vol_threshold=1.2, return_threshold=0.008, 
     top_n=20)). Both filters pull from the same activity-biased top-80 pool
     (use_full_universe=False) and rank by the same opportunity_score — they
     select nearly-identical symbol sets.
     2. QuietBreakoutStrategy.decide() requires price > high_20d. Whenever its
     signal fires, price > high_10d is also true →
     BreakoutMomentumStrategy.decide() fires on the same symbol on the same bar.
     3. MultiStrategyRouter._merge_into() (multi_router.py:281-326) resolves
     equal-priority BUYs by weight. At equal weight, the iteration order is
     deterministic but uniformly disadvantageous to QuietBrk; over thousands of
     bars, Breakout owns essentially every position. QuietBrk's dropped_priority
      counter goes up; won_merge stays at 0.
     4. Once Breakout owns a symbol, the ownership rule
     (multi_router.py:198-203) prevents QuietBrk from ever entering or exiting
     it.

     Intended outcome: Give QuietBrk a structurally orthogonal universe slice —
     stocks Breakout's own entry criteria (vol_ratio > 1.2, |daily_return|
     effectively > 1.5%) will reject. QuietBrk's 20-day breakout signal then has
      a population of slow-grinding stocks to find genuine entries in, where
     Breakout doesn't compete.

     This is the "QuietBrk routing carve-out" lever identified in the
     conversation as the highest-upside untouched intervention. It is not a
     universe rescore (see [[feedback-universe-not-the-bottleneck]] — that
     experiment changed scoring weights for the shared universe and did not move
      opportunity-quality metrics). It is also not a bare use_full_universe=True
      flip (see [[feedback-universe-filter-bypass]] — that activation alone,
     without a new criterion, didn't help). It is a new filter class with new
     criteria that produces a different cohort entirely.

     Approach

     Soft carve with middle-band quiet criteria + overlap instrumentation.

     1. Add QuietBreakoutUniverseFilter in app/universe/filters.py. Selects from
      the full-150 pool (use_full_universe = True). Cross-sectional percentile
     gates per day:
       - atr_ratio in the 25th–60th percentile band of today's pool
       - rolling_vol_5d in the 25th–60th percentile band of today's pool
       - |daily_return| < 0.015 (no big move today)
       - relative_volume in [0.7, 1.5] (normal-ish volume — not dead, not
     spiking)
       - Rank by rolling_vol_5d ascending (calmest first) to give QuietBrk the
     slowest-grinding tail of the band
       - top_n = 20
     2. Wire it into the union in run_ujjwal_baseline.py:160-166. Order:
     BreakoutUniverseFilter first, then QuietBreakoutUniverseFilter. The
     existing UnionUniverseFilter.select_universe() dedup loop
     (filters.py:370-378) already gives priority to whichever filter appears
     first — Breakout wins on any overlap with zero new code paths.
     3. Overlap instrumentation in UnionUniverseFilter. Add a per-filter counter
      (absorbed_by_earlier) that increments each time a filter's selected
     candidate is dropped because a prior filter already claimed it. Expose via
     get_overlap_stats() returning {filter_index: count}. Print average overlap
     per day at end-of-period in run_ujjwal_baseline.py.

     Critical files

     File: app/universe/filters.py
     Change: Add QuietBreakoutUniverseFilter class (sibling of
       BreakoutUniverseFilter, ~50 lines). Modify UnionUniverseFilter to track
       per-filter absorbed_by_earlier counts inside the dedup loop and expose

     ────────────────────────────────────────

     No changes to:
     - MultiStrategyRouter — overlap is handled by the existing dedup ordering;
     orthogonal criteria mean Breakout's strategy code will rarely fire on
     QuietBrk's slice anyway
     - BreakoutMomentumStrategy / QuietBreakoutStrategy — they continue to
     consume symbol_states unchanged
     - app/backtest/engine.py — already passes both broad_candidates and
     all_candidates to the union filter; the use_full_universe=True path is

     Implementation notes

     - Percentiles computed per day from the candidate pool's atr_ratio and
     rolling_vol_5d values. numpy.percentile or pure-Python sorted()[idx]. If
     the pool has fewer than 4 candidates with non-zero values, skip the
     percentile gate and use a fixed fallback (atr_ratio < 0.04, rolling_vol_5d 
     < 0.025) — protects warm-up days.
     - Mirror the existing filter conventions: take init params (band edges,
     top_n) with defaults; implement select_universe(candidates) and
     select_symbols(candidates, all_candidates=None); set use_full_universe = 
     True as class attribute. Pattern is PullbackUniverseFilter
     (filters.py:81-140) — same percentile-band shape.
     - Overlap counter location: in UnionUniverseFilter.select_universe()
     (filters.py:350-378), the existing if candidate.symbol not in seen branch
     is where overlap is not absorbed. The else of that branch is where overlap
     happens. Increment a per-filter-index counter there.
     - Output format at end-of-period: one line per filter showing average
     overlap count per day (QuietBrk filter: 1.4 names/day absorbed by earlier 
     filters (max 7)) — gives at-a-glance read on whether the carve is
     structurally clean.

⏺ Good diagnostic catch. The universe carve worked perfectly (overlap is
  0.00/day — confirms Breakout and QuietBrk get fully orthogonal stocks). The
  problem is one layer up.

  What we got wrong

  The universe filter only controls which symbols enter the merged active list —
   but every strategy in the router still sees all active symbols. So:

  1. QuietBrk's universe gives it stock X (low-vol, quiet)
  2. The merged active_symbols includes X (union of both filters' picks)
  3. Both strategies see X in their symbol_states dict
  4. For X: price > high_20d triggers QuietBrk BUY → but price > high_10d ALSO
  triggers Breakout BUY (because high_10d is a subset window of high_20d)
  5. Breakout's vol_ratio > 1.2 entry guard is permissive enough that QuietBrk's
   quiet stocks (relative_volume 0.7–1.5) often pass it
  6. Both fire BUY → merge → tied on action → Breakout wins on weight/iteration
  → owns the position

  Evidence in your numbers:
  - QuietBrk prio_loss: 39,816 (baseline) → 37,032 (now). Only -7%, so Breakout
  is still poaching almost all of QuietBrk's stocks.
  - Breakout signals_issued: 54,165 → 50,725 (-6%). Lost ~3k signals (the stocks
   QuietBrk uniquely got that Breakout no longer sees in its universe slot), but
   still fires on basically everything QuietBrk now sees in symbol_states.

  The carve-out works at the universe layer, but the strategies still see each 
  other's slices. They need to be blinded to symbols outside their assigned
  slice.

  The fix

  Per-strategy universe gating at the router level. Each strategy only sees the
  symbol_states for symbols its own universe filter selected. This is the
  architecturally correct fix and reuses existing scaffolding:

  1. Tag filters in the union — change UnionUniverseFilter([f1, f2, ...]) to
  support UnionUniverseFilter([("Breakout", f1), ("QuietBrk", f2), ...]). After
  each select_universe() call, expose last_per_strategy_symbols: {strategy_name:
   set[symbol]}.
  2. Router gate — MultiStrategyRouter accepts an optional
  per_strategy_universe_source: callable() -> dict. In _dispatch(), before the
  regime filter, gate symbol_states to the strategy's assigned slice. Held
  positions and cross-exit strategies still bypass (existing logic preserved).
  3. Wire both runners — pass tagged filters + the callable into each router
  instance.

  Solo strategy runs are unaffected (no router involved; each gets its own
  universe filter directly). Untagged unions remain backwards-compatible (the
  gate no-ops if no slice is recorded for a strategy).

     Plan — Asymmetric Universe Gate (QuietBrk Exclusive Slice Only)

     Context

     We've run two experiments on QuietBrk's 0-contribution problem and rolled
     both back:

     1. Middle-band quiet filter alone (filters.py change). Gave QuietBrk a
     structurally different universe slice. Overlap with Breakout went to 0/day
     at the universe layer. But QuietBrk still won 0 entries — because the
     router still showed every strategy the merged active_symbols, so Breakout's
      vol_ratio > 1.2 strategy gate fired on QuietBrk's quiet stocks anyway.
     2. Symmetric per-strategy router gate (multi_router.py change). Every
     tagged strategy was blinded to symbols outside its assigned slice.
     Mechanism worked — QuietBrk finally entered trades. But cost was severe:
     Adapt+RCA regressed −4.85pp Crash, −2.75pp Bear, −9.47pp Recent, with only
     a +2.35pp gain in Recov. The full gate stripped Breakout of 70%+ of its
     poaching surface, and Breakout's poaching turned out to be doing real work
     in most regimes. Pattern matches [[feedback-cross-strategy-exit-failed]]:
     any broad cap on Breakout helps Live but hurts Crash/Recov/Recent.

     This plan tries a third, asymmetric variant. Keep the universe carve
     (QuietBrk's exclusive slice exists). Apply the router gate only to 
     QuietBrk: QuietBrk operates on its private slice; every other strategy
     continues to see the merged universe with one small exclusion — QuietBrk's
     reserved symbols are removed from their view. Net effect:

     - Breakout loses ~8 symbols/day (QuietBrk's slice) — ~10% of its 80-stock
     merged-universe surface
     - Breakout keeps 100% of its poaching on TrendPB, RSI-MR, DualMA slices
     (the bulk of where it was winning in Recent and Recov)
     - QuietBrk gets an uncontested lane to express its standalone Sharpe-2
     behavior
     - TrendPB, RSI-MR, DualMA see (merged − QuietBrk slice) — virtually
     unchanged from current behavior

     Intended outcome: A targeted intervention that gives QuietBrk a real chance
      to contribute without re-triggering the broad Breakout regression that
     killed Experiment 2.

     Honest expectation: The Breakout-capping asymmetry still partially applies
     — Breakout still loses some universe surface. Best case: QuietBrk adds +1
     to +3pp in Crash/Recov/Recent (where its standalone Sharpe is 2+) and
     Breakout loses only −0.5 to −1pp. Worst case: QuietBrk's slice is too
     narrow to generate meaningful trade volume even uncontested (~20
     trades/period vs ~250 standalone), and we end up roughly net neutral. Per
     [[feedback-cross-strategy-exit-failed]] we should treat this as a final
     test of the carve-out idea — if it's net negative or neutral, document and
     stop.

     Approach

     Single router-layer change: add exclusive_strategies: set[str] to
     MultiStrategyRouter. Semantics in _dispatch:

     - If name in exclusive_strategies: gate symbol_states to that strategy's
     slice only (existing per-strategy gate behavior, scoped to exclusive
     strategies).
     - Else (any exclusive strategies configured): gate symbol_states to
     (everything not in any exclusive strategy's slice). Preserves the
     merged-universe view minus reserved symbols.
     - Else (no exclusive strategies): legacy behavior, no filtering.

     All existing bypass rules preserved (held positions owned by this strategy,
      untracked positions, cross-exit strategies see all held positions).

     Wire exclusive_strategies={"QuietBrk"} into every router site. The
     universe-layer tagged-filter scaffolding is already in place from
     Experiment 2 and stays untouched.

  The actual diagnosis (this is where your intuition is right)

  The QuietBrk slice we built isn't QuietBrk's natural universe — it's the wrong
   kind of "quiet."

  Look at what we did:
  - QuietBreakoutUniverseFilter picks stocks where atr_ratio is in the
  bottom-middle band, rolling_vol_5d in the bottom-middle band, |daily_return| <
   1.5%, relative_volume in [0.7, 1.5].
  - That's structurally inactive stocks. Low range, low recent volatility, no
  daily move.

  But QuietBrk's strategy entry is price > high_20d with vol_ratio > 1.2. That
  signal needs movement to fire. A stock that hasn't moved more than 1.5% on the
   day, sitting in the low band of ATR for weeks, almost never breaks above its
  20-day high with above-average volume.

  Standalone QuietBrk uses the relaxed-Breakout filter (vol > 1.2, |return| >
  0.008) — that's active stocks, just slightly less explosive than Breakout's
  strict cutoff. That's where the 20-day breakouts actually happen.

  So the routing fix is right; the universe definition for QuietBrk is wrong.
  We've been giving it the dead pool when it actually wants the second-tier
  active pool.

  The fix: "activity tail" instead of "structurally quiet"

  Replace QuietBreakoutUniverseFilter with a filter that selects stocks
  Breakout's strict thresholds reject but that are still active enough for
  20-day breakouts to fire. Concretely:

  - Exclude stocks Breakout would take (vol_ratio > 1.5 AND |daily_return| >
  1.5%) — these belong to Breakout
  - Include stocks with vol_ratio > 1.0 AND |daily_return| > 0.5% — moderate
  activity, still moves
  - Operate on the top-80 broad pool (where activity exists)
  - Top 20 by score

  This is essentially QuietBrk's standalone universe minus Breakout's strict
  picks. The exclusive-gate already prevents Breakout from poaching these (since
   it's reserved for QuietBrk). And QuietBrk gets a universe where its signal
  actually triggers.

  Expected effect:
  - QuietBrk trades/period: 1–5 → likely 20–60 (closer to standalone)
  - Breakout signals: stays at ~94% retention (we're only reserving an
  "in-between" band)
  - The structurally-quiet stocks we currently reserve will go back into the
  merged universe where Breakout/TrendPB/etc. can use them if they want (most
  won't, those stocks are dead)
  - Net should be: QuietBrk meaningfully contributes for the first time, no
  further Breakout regression

  The Recov Adapt+RCA wrinkle (worth flagging)

  Adapt+RCA Recov dropped −5.79pp from sym gate (87.32%) to asym gate (81.53%).
  Why: the symmetric gate had a hidden benefit — DualMA's lane was uncontested
  and its Adapt+RCA PnL went from +332 baseline → +4,683 (+4,351 lift).
  Asymmetric gate gives DualMA back to the merged-minus-QuietBrk pool, where
  TrendPB/RSI-MR muddy the merge → DualMA only +1,107.

  So there's a real signal that DualMA also benefits from an exclusive lane. But
   making DualMA exclusive too cuts deeper into Breakout's surface. That's a
  future trade-off to consider; for now, single-exclusive is the right scope.

⏺ Verified the actual code. The agent's audit had some right ideas but
  mis-attributed several specifics. Here's the actual diagnosis based on what I
  confirmed in the code.

  Is QuietBrk working in Full period?

  Yes — clearly. Full 2018–2024 EqW return jumped from 76.87% → 82.35%
  (+5.48pp). Adaptive (no RCA) went 120.15% → 129.64% (+9.49pp). QuietBrk
  contributes ₹12,926 in EqW (16.7% share), ₹16,248 in Adapt+RCA (14.5% share).
  The architecture change is doing its job.

  The thing that broke is RCA's value-add, not QuietBrk. RCA delta went from
  +10.54pp baseline → −8.79pp Exp 4. That's a 19pp swing in what RCA contributes
   on top of Adaptive.

  How RCA actually works (verified)

  RCA does three things, not just one:

  1. Computes trend and broad_regime from the 150-symbol DynamicUniverseAgent 
  cache (regime_context_agent.py:33–57). Independent of the active universe
  filter.
  2. Enables two regime labels that don't exist without RCA: TRANSITION_UP
  (adaptive_selector.py:66–69) requires snapshot.get("trend") == "IMPROVING" —
  and trend is only set by RCA. Same for BEAR_EARLY detection nuances. Without
  RCA, the classifier can never produce these labels.
  3. Triggers CB relaxation in the engine (engine.py:204–210). When broad_regime
   == "TRANSITION_UP" the downtrend cap drops to 30%; BEAR_EARLY → 38%. This is
  a risk-side effect completely independent of the LLM.

  So RCA has three coupled value-add paths (regime detection / LLM prompt
  content / CB relaxation), all keyed off the same broad_regime signal. When the
   signal is accurate, all three help. When it's wrong or thrashing, all three
  hurt.

  What the agent got right (verified)

  - _REGIME_RULES[0] (TRANSITION_UP) is RCA-exclusive (adaptive_selector.py:68).
   Without RCA, trend is None, so this rule can never fire. RCA "unlocks" this
  regime. Verified ✓
  - CB relaxation is RCA-driven (engine.py:204–210). Verified ✓
  - Snapshot history is appended after every rebalance
  (adaptive_selector.py:411–420). The history block goes into every LLM prompt
  and is sensitive to universe composition. Verified ✓

  What the agent got wrong

  - "Dict iteration causes different sum()" — false. pct_above_sma50_broad = 
  sum(0/1 values) / n_b is order-independent. Floating-point differences are too
   small to flip regime thresholds. Not a real bug.
  - "State leakage between periods in _history" — false. PeriodContext.__init__
  creates a fresh RegimeContextAgent per period (run_experiments.py uses
  ctx.regime_context_agent from the new context). No leakage in practice. Not a 
  real bug.
  - "Double regime classification with conflicting inputs" — false in practice.
  RCA and selector both call the same _classify_regime function on the same
  merged snapshot, so they produce the same label. Verified by reading the code
  path.

  The actual sources of RCA inconsistency

  Ranked by impact:

  1. LLM call non-determinism (biggest factor)
  - temperature=0.0, seed=0 is best-effort per OpenAI's docs
  (adaptive_selector.py:446–447)
  - Full period makes 337 LLM calls — small per-call variance compounds heavily
  - RCA's prompt is LONGER (extra 5-line breadth block,
  adaptive_selector.py:586–592), more surface for subtle tokenizer-level
  variation
  - Memory same_run_analysis.md already documented Adapt-only seeing ~3.95pp
  variance; Adapt+RCA can easily double that
  - This is not a fixable bug — it's a property of the API

  2. Compound RCA effects (architecture-level)
  - One regime-flip cascades into 3 places: LLM prompt → different weights, CB
  threshold → different gate behavior, regime stability → different switch
  timing
  - When the underlying market is in a CLEAR regime (Recov 2020), all 3 paths
  align and RCA adds +6.69pp
  - When the market is choppy (Bear 2022), the 3 paths can conflict and RCA
  drags −2.66pp
  - Not strictly a bug, but an amplifier on regime-detection noise

  3. Active-universe sensitivity
  - When ActivityTailFilter swaps QuietBrk's slice, pct_uptrend / pct_downtrend 
  / avg_atr_pct shift slightly
  - Those numbers feed _classify_regime for the active universe
  - Borderline cases flip → different LLM prompt → different weights
  - The history block (last 4 weekly snapshots) carries these subtle differences
   forward, magnifying the effect over the period

  Fixes worth doing (ranked)

  Fix: LLM response cache (key = SHA256 of prompt text, value = parsed weight
    dict)
  Effort: ~30 LOC
  What it solves: Identical prompts → identical responses across runs.
  Eliminates
    LLM variance entirely. Already suggested in memory
    [[feedback-cross-strategy-exit-failed]].
  ────────────────────────────────────────
  Fix: Round all numeric values in the prompt to 2 decimal places + omit date
    strings from history block
  Effort: ~15 LOC
  What it solves: Reduces LLM prompt sensitivity to noise; more prompts will
    hash-collide with the cache
  ────────────────────────────────────────
  Fix: Make CB relaxation read selector's _confirmed_regime instead of RCA's raw

    broad_regime
  Effort: ~5 LOC
  What it solves: Eliminates the chance of selector and engine disagreeing on
    regime label during a pending transition
  ────────────────────────────────────────
  Fix: Decouple trend computation from RCA — let selector compute it from its
  own
    history when RCA is absent
  Effort: ~10 LOC
  What it solves: Removes RCA-exclusivity for TRANSITION_UP/BEAR_EARLY
  detection;
    reduces Adapt-vs-RCA asymmetry

  My recommendation: do the LLM cache first. It's the highest-leverage single
  change because:
  - It makes ALL future A/B comparisons truly deterministic (same prompt = same
  response, no exceptions)
  - It would have prevented you from being unable to tell whether the 19pp RCA
  swing was from your filter change or from LLM noise
  - It pays for itself in API cost reduction on repeat runs
  - Memory already flags this as a known limitation

  The cache would key on SHA256(prompt_text) → (weights_dict, raw_response),
  stored as a JSON file on disk. First call hits OpenAI; subsequent identical
  prompts return instantly. Across A/B comparisons of the same backtest harness,
   ~95%+ of prompts will be identical (different runs against the same market
  data produce mostly identical regime snapshots), making your A/B noise drop
  dramatically.
